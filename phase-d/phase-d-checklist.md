# Phase D Checklist

Riferimento: [specifiche complete](../docs/specs.md).

## 1. Team card

- [ ] Ripetere la Team card delle fasi precedenti senza variazioni non motivate.

## 2. Preparazione della valutazione

- [ ] Identificare e congelare la versione da valutare.
- [ ] Definire task e criteri di successo.
- [ ] Riutilizzare, quando possibile, metodi e metriche della Fase A.
- [ ] Preparare schede, protocollo, dati attesi e responsabilità del team.
- [ ] Distinguere chiaramente inspection interna e test con persone reali.

## 3. Inspection

- [ ] Selezionare una o più tecniche pertinenti.
- [ ] Eseguire un Cognitive Walkthrough passo-passo sui task principali.
- [ ] Eseguire una Action Analysis quando serve quantificare le azioni.
- [ ] Eseguire una Heuristic Analysis con guideline definite.
- [ ] Far lavorare i valutatori separatamente quando previsto.
- [ ] Consolidare i risultati in gruppo.
- [ ] Per ogni finding indicare versione, task, schermata e metodo.
- [ ] Assegnare severità e priorità con criteri dichiarati.
- [ ] Formulare raccomandazioni concrete.
- [ ] Correggere il prototipo.
- [ ] Documentare il passaggio tra versione iniziale e versione post-ispezione.
- [ ] Collegare ogni modifica della versione post-ispezione alla raccomandazione di Cognitive Walkthrough o Heuristic Analysis che l'ha originata.

**Deliverable:** Inspection card, schede individuali e changelog.

## 4. User testing del redesign

- [ ] Definire se il test è formativo o sommativo.
- [ ] Reclutare persone reali appartenenti ai segmenti.
- [ ] Coinvolgere almeno due partecipanti della sessione preliminare di Fase A.
- [ ] Motivare l'uso degli stessi partecipanti o di partecipanti diversi.
- [ ] Mantenere un intervallo adeguato tra test ripetuti.
- [ ] Usare task confrontabili con quelli della Fase A.
- [ ] Applicare metriche consolidate.
- [ ] Includere almeno una misura di soddisfazione.
- [ ] Eseguire un pilot del protocollo.
- [ ] Condurre i test senza guidare i partecipanti.
- [ ] Compilare una Test Data card per ogni partecipante.
- [ ] Raccogliere successo, tempo, efficacia, errori, learnability e osservazioni.
- [ ] Somministrare il SUS standard.
- [ ] Inserire le tabelle quantitative nella documentazione.
- [ ] Calcolare risultati individuali, media e varianza.
- [ ] Dichiarare deviazioni, limiti, bias ed effetto apprendimento.

**Deliverable:** Redesign User Testing card, card individuali, dati e SUS.

## 5. Iterazione formativa

- [ ] Aggregare problemi quantitativi e qualitativi.
- [ ] Costruire una curva d'urgenza.
- [ ] Collegare ogni problema a una evidenza del test.
- [ ] Prioritizzare le correzioni.
- [ ] Creare una nuova versione del prototipo.
- [ ] Aggiornare blueprint, wireframe, Before/After e Design card.
- [ ] Documentare tutte le modifiche nel changelog.
- [ ] Ripetere design e testing se i risultati sono ambigui o insoddisfacenti.

## 6. Valutazione sommativa

- [ ] Congelare la versione finale prima del test.
- [ ] Non modificare il prototipo durante la raccolta dati.
- [ ] Preferire partecipanti nuovi per limitare l'effetto apprendimento.
- [ ] Ripetere task, condizioni e metriche confrontabili.
- [ ] Calcolare risultati individuali e aggregati.
- [ ] Confrontare sistema originale e redesign.
- [ ] Separare risultati osservati e interpretazioni.
- [ ] Registrare anche risultati negativi o inattesi.

## 7. Conclusioni e raccomandazioni finali

- [ ] Riprendere gli obiettivi iniziali.
- [ ] Dichiarare ciò che il progetto ha raggiunto e ciò che non ha raggiunto.
- [ ] Sostenere ogni conclusione con dati e numeri.
- [ ] Interpretare i risultati senza generalizzazioni eccessive.
- [ ] Confrontare qualitativamente e quantitativamente prototipo e originale.
- [ ] Evidenziare punti di forza e debolezza.
- [ ] Descrivere errori del team e relative correzioni.
- [ ] Proporre attività future per aumentare affidabilità dei risultati.
- [ ] Proporre eventuali miglioramenti funzionali.
- [ ] Proporre ulteriori miglioramenti di usabilità.

**Deliverable:** Project Conclusion card.

## Controllo finale della fase

- [ ] Team card presente.
- [ ] Versione valutata identificata senza ambiguità.
- [ ] Inspection documentata.
- [ ] Test svolti con persone reali.
- [ ] Almeno due partecipanti provengono dalla Fase A.
- [ ] Metriche e SUS sono verificabili dai dati grezzi.
- [ ] Tabelle quantitative incluse nella documentazione.
- [ ] Iterazioni motivate dai risultati.
- [ ] Confronto finale con il sistema originale completato.
- [ ] Conclusion card completa di risultati, limiti e lavoro futuro.
